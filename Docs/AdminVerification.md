# Админка верификации Sweetgram

Право выдать галочку больше не хранится в приложении. Ни пароля, ни
секрета в APK нет: право решают правила Realtime Database по
`auth.uid` вошедшего.

## Как это работает

1. Пункт «Admin panel» открывает форму входа: почта и пароль Firebase Auth.
2. После входа клиент сверяется с узлом `admins` в базе: если вошедшего там
   нет — сессия сбрасывается, панель не показывается.
3. Затем клиент сверяет **телеграм-ID активного аккаунта** со списком
   `tg_admins`: чужой телеграм-ID из панели выкидывает, даже если он
   как-то прошёл первый шаг. Свой ID виден на экране входа — строка
   «Your Telegram ID: …».
4. Выдача и отзыв пишут напрямую в `verified_users/<uid>`. Правила разрешают
   запись только тому, чей uid есть в `admins`, — так что без списка ничего
   не выйдет, и приложение честно покажет ошибку.

Проверка по телеграм-ID живёт в приложении: сервер Firebase о телеграме
ничего не знает и проверить ID не может. Врать ей может только
распатченный клиент — а патченный клиент и так не пройдёт правила записи.
Поэтому двух ступеней достаточно: пароль решает, «свой ли это владелец»,
телеграм-ID — «та ли это учётка телеграма». Сессия входа переживает
перезапуски приложения, но телеграм-ID перепроверяется при каждом
открытии панели: убрал себя из списка — панель закрылась.

## Разовая настройка

1. Firebase Console → проект Sweetgram → **Authentication → Sign-in method**
   → включить **Email/Password**.
2. **Authentication → Users → Add user**: завести админа (почта + пароль) и
   скопировать его **UID**.
3. Realtime Database → два узла в корне:
   - `admins/<UID> = true` — UID из шага 2;
   - `tg_admins/<телеграм_id> = true` — ID твоего аккаунта в телеграме
     (панель показывает его на экране входа, строка «Your Telegram ID»).
4. Задеплоить правила из этого репозитория:

   ```
   firebase deploy --only database
   ```

   (нужен [Firebase CLI](https://firebase.google.com/docs/cli) и
   `firebase init` с привязкой к проекту) — либо вставить содержимое
   `database.rules.json` в консоли: Realtime Database → Rules → Publish.

Старое правило с секретом в `verified_meta` становится не нужно: новые
правила писать туда запрещают совсем.

## Что защищено, а что нет

- Пароль админа и allowlist не вытекают из APK — их там просто нет.
- В панель входит только тот, чей телеграм-ID записан в `tg_admins`, и
  только с паролем от своего аккаунта Firebase.
- Сам клиент по-прежнему можно распатчить и выдавать галочки локально, у
  себя на экране — это свойство любого клиента, и локальная галочка
  видна только тому, кто её себе нарисовал.
- Публичное чтение `verified_users` оставлено намеренно: это и есть
  источник правды для всех клиентов форка.
